# セキュリティ・秘密情報・認証

## 基本
- すべての外部入力を信頼できないデータとして扱う。
- SQLはパラメータ化クエリを使う。OSコマンドに外部入力を直接連結しない。
- HTMLは出力コンテキストに応じてエスケープする（XSS対策）。CSRF対策も行う。
- 入力検証はクライアント側だけでなくサーバー側でも行う。
- 最小権限の原則に従う。安全な既存機能を理由なく弱体化させない。
- セキュリティ機能を無効化したまま完成扱いにしない。

## 秘密情報・個人情報
- APIキー、トークン、パスワード、秘密鍵をコードに埋め込まない。環境変数やシークレット管理機構を使う。
- .env等の機密ファイルをGitに登録しない（.gitignoreで除外）。
- フロントエンドにサーバー側の秘密情報を渡さない。
- ログ、エラーメッセージ、テストデータに機密情報を出さない。
- パスワードは適切なハッシュ方式（bcrypt / argon2 等）で保存する。
- 個人情報・取引情報の外部送信は最小限にし、外部AI・外部APIへの機密データ送信は事前承認を得る。
- テストでは実データより匿名化・合成データを優先する。

## 認証・認可・通信
- 認証と認可を分離し、権限はサーバー側で検証する（画面の表示制御だけに頼らない）。
- 他ユーザーの情報を不正に参照できない設計にする。
- Cookieには必要に応じて Secure / HttpOnly / SameSite を設定する。
- 通信は原則HTTPS。外部通信先・リダイレクト先・アップロード先を検証する。
