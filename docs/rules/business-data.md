# 業務データ・外部データ連携・監査

## CSV・Excel・外部連携
- 取込ファイルの形式、文字コード、列構成、必須項目を検証する。
- 引用符、改行、区切り文字を正しく扱う。識別コードの先頭ゼロを維持する。
- 重複取込・二重登録・部分失敗を考慮し、正常行とエラー行を識別できるようにする。
- 不正データを黙って破棄・補完しない。
- CSV出力では数式インジェクション（=, +, -, @ で始まる値）に注意する。
- 外部APIのタイムアウト、レート制限、再試行を考慮する。

## 業務データのルール
- 商品・仕入先・得意先は安定したキーで識別し、表示名だけで一意性を判断しない。
- JANコード、独自商品コード、ケース入数、単位を区別する。
- 原価、売価、仕切値、値引、リベートを混同しない。
- 税率、税区分、端数処理の仕様を明確にする。
- 取引条件には必要に応じて有効開始日・終了日を設ける。
- 過去の見積・受注・売上は当時の条件で再現できるよう、必要な値を明細や履歴に保持する。
- 変更履歴と最新マスタを混同しない。
- 在庫の入庫・出庫・移動・調整の区分を明確にする。
- 不明な業務ルールを一般常識で決めつけず、ユーザーに確認する。

## 監査・追跡
- 重要な登録・変更・削除には監査ログ（日時、操作者、対象、変更前後）を検討する。
- 監査ログの改ざん・無断削除を防ぐ。個人情報を過剰に保存しない。
